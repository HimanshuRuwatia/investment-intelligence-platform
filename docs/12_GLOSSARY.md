# Purpose

This document defines the official vocabulary of the Investment Intelligence Platform.

Every important term used throughout the repository MUST be defined here.

The goals are:

* Eliminate ambiguity.
* Ensure consistent terminology.
* Improve documentation quality.
* Improve AI-generated code consistency.
* Prevent synonym drift.

No document should introduce a new architectural or domain term without first defining it here.

---

# Terminology Rules

The following rules apply throughout the project.

* Every important concept has exactly one canonical name.
* Avoid inventing synonyms for existing concepts.
* Definitions should remain stable.
* When in doubt, reference this document.

Example:

Preferred:

* Plugin

Avoid:

* Module
* Service
* Component

unless they refer to genuinely different concepts.

# Core Concepts

---

## Platform

### Definition

The complete financial intelligence system.

The Platform consists of:

* Platform Core
* Plugins
* Shared Infrastructure
* Documentation
* Local Tooling

The Platform is the complete application.

---

## Platform Core

### Definition

The shared infrastructure responsible for orchestrating the Platform.

### Responsibilities

* Plugin lifecycle
* Scheduling
* Configuration
* Shared services
* Evidence storage
* Reasoning orchestration

### MUST NOT

Contain financial business logic.

---

## Plugin

### Definition

A Plugin represents one business capability.

Examples include:

* Performance
* Risk
* Benchmark
* Holdings
* Strategy
* Manager
* Macro

Plugins are independently developed and independently testable.

# Data Concepts

---

## Raw Data

### Definition

Information collected directly from external sources.

### Examples

* NAV history
* Holdings
* News
* RBI announcements
* Inflation
* GDP
* Interest rates

Raw Data has not yet been analyzed.

---

## Normalized Data

### Definition

Raw Data converted into the Platform's internal format.

Normalization removes inconsistencies while preserving meaning.

---

## Metric

### Definition

A deterministic numerical value calculated from data.

### Examples

* CAGR
* Rolling Return
* Sharpe Ratio
* Sortino Ratio
* Maximum Drawdown
* Alpha
* Beta

Metrics are reproducible.

---

## Evidence

### Definition

Structured information supporting a financial conclusion.

Evidence is generated by deterministic analyzers.

Evidence MUST NOT be generated by an LLM.

### Typical Contents

* Metrics
* Metadata
* Timestamp
* Confidence
* Source

Evidence is the primary information exchanged inside the Platform.

---

## Signal

### Definition

A meaningful relationship detected from Evidence.

Signals explain what changed.

### Examples

* Sector rotation detected.
* Portfolio concentration increased.
* Volatility rising.
* Strategy shifted toward value investing.

Signals are observations rather than conclusions.

---

## Knowledge

### Definition

Stable understanding accumulated from repeated Signals.

Knowledge represents patterns observed across long periods.

### Example

"The manager consistently increases manufacturing exposure before earnings upgrades."

Knowledge evolves gradually.

---

## Insight

### Definition

A human-readable explanation generated by the LLM.

Insights combine:

* Evidence
* Signals
* Knowledge

Insights communicate understanding.

Insights are not deterministic calculations.

---

## Score

### Definition

A deterministic numerical evaluation produced by the Decision Engine.

Examples include:

* Performance Score
* Risk Score
* Consistency Score
* Overall Score

Scores are inputs to reasoning.

---

## Confidence

### Definition

A measure of how strongly available evidence supports a conclusion.

Confidence reflects uncertainty.

Confidence should accompany:

* Evidence
* Signals
* Knowledge
* Insights

---

# Processing Concepts

---

## Collector

### Definition

A component responsible for acquiring Raw Data.

### Responsibilities

* Fetch data
* Validate responses
* Handle retries

### MUST NOT

* Analyze data
* Calculate metrics
* Call LLMs

---

## Normalizer

### Definition

A component responsible for converting external data into standardized internal models.

### Responsibilities

* Validate
* Standardize
* Clean
* Transform

Normalizers never perform financial analysis.

---

## Analyzer

### Definition

A deterministic component responsible for producing Metrics.

### Responsibilities

* Calculate metrics
* Produce Evidence

### MUST NOT

* Fetch data
* Call LLMs
* Generate explanations

---

## Detector

### Definition

A deterministic component responsible for identifying Signals.

Detectors consume Evidence.

Detectors produce Signals.

---

## Knowledge Builder

### Definition

A component responsible for converting repeated Signals into long-term Knowledge.

Knowledge Builders improve understanding over time.

---

## Decision Engine

### Definition

A deterministic engine responsible for generating Scores and Rankings from Evidence.

The Decision Engine is the source of financial evaluation.

---

## Reasoning Layer

### Definition

A component responsible for preparing structured context for the LLM.

Responsibilities include:

* Collecting Evidence
* Selecting Signals
* Selecting Knowledge
* Prioritizing information
* Reducing token usage

The Reasoning Layer does not perform financial analysis.

---

## LLM

### Definition

The Large Language Model used by the Platform.

Responsibilities:

* Explain
* Summarize
* Compare
* Answer questions
* Generate reports

### MUST NOT

* Calculate deterministic metrics
* Invent Evidence
* Override deterministic outputs

# Development Concepts

---

## Vertical Slice

### Definition

A complete end-to-end implementation of one business capability.

A Vertical Slice includes:

* Data collection
* Analysis
* Evidence
* Storage
* Reasoning
* Local interaction

The project is developed one Vertical Slice at a time.

---

## Local First

### Definition

A development strategy where every feature must work locally before considering cloud deployment.

---

## Deterministic

### Definition

A process that always produces the same output for the same input.

Deterministic components are reproducible and testable.

---

## Explainability

### Definition

The ability to explain:

* Why a conclusion exists.
* Which evidence supports it.
* Which metrics contributed.
* How confident the Platform is.

Explainability is a core requirement.

# Repository Concepts

---

## Documentation

### Definition

Project knowledge stored as Markdown files.

Documentation is considered part of the codebase.

---

## ADR (Architecture Decision Record)

### Definition

A document recording an important architectural decision.

An ADR captures:

* Context
* Decision
* Alternatives
* Rationale
* Consequences

ADRs explain why the architecture evolved.

# Canonical Flow

The Platform processes information using the following pipeline.

```text
Raw Data
    ↓
Normalized Data
    ↓
Metrics
    ↓
Evidence
    ↓
Signals
    ↓
Knowledge
    ↓
Scores
    ↓
Reasoning Context
    ↓
LLM
    ↓
Insight
```

Every component in the Platform contributes to one stage of this flow.

| Knowledge Builder | Produces Knowledge                  |
| Decision Engine   | Produces Scores                     |
| Reasoning Layer   | Builds LLM context                  |

| Signal            | Relationship detected from Evidence |

| Insight           | Human-readable explanation          |

These definitions are canonical and should be used consistently throughout the project.
